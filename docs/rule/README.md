# AI 코더 개발 룰 가이드

## 개요
이 폴더는 AI 코더가 프론트엔드 개발 시 준수해야 할 모든 지침과 룰을 정리한 문서들을 포함합니다.

## 📋 문서 목록

### 1. [개발 워크플로우 지침](./development-workflow.md)
**필수 숙지 문서** - 모든 기능 개발의 기본 플로우

- TDD 기반 8단계 개발 프로세스
- 컴포넌트 테스트 → 구현 → 스토리북 → 통합 테스트 순서
- 각 단계별 상세 작업 내용 및 체크리스트
- 트러블슈팅 가이드

### 2. [코딩 표준 지침](./coding-standards.md)
코드 품질과 일관성을 위한 표준

- TypeScript 코딩 규칙
- React 컴포넌트 작성 규칙
- 파일 및 폴더 구조 규약
- 네이밍 컨벤션
- 코드 리뷰 체크리스트

### 3. [테스트 작성 지침](./testing-guidelines.md)
효과적인 테스트 작성을 위한 가이드

- Jest 테스트 환경 문제 해결 (import.meta.env 에러 등)
- React Context 및 컴포넌트 Mock 패턴
- TDD RED → GREEN → BLUE 사이클
- 테스트 파일 구조 템플릿
- 자주 발생하는 에러와 해결책

### 4. [보안 지침](./security-guidelines.md)
보안을 고려한 안전한 코드 작성

- XSS/CSRF 방지 기법
- JWE 토큰 보안 처리
- AWS 보안 설정
- 환경변수 관리
- API 통신 보안

### 5. [컴포넌트 설정 지침](./component-configuration.md)
프로젝트 컴포넌트 사용법 및 설정

- FAQ 카테고리 아이콘 설정
- 주요 컴포넌트 사용 예시
- 커스텀 훅 활용법
- 환경변수 설정 방법

## 🚨 중요 사항

### 필수 준수 룰
1. **[개발 워크플로우](./development-workflow.md)의 8단계 프로세스는 반드시 순서대로 진행**
2. **테스트 없이 구현 시작 금지**
3. **모든 단계에서 테스트 통과 후 다음 단계 진행**
4. **make all-tests 통과 없이 작업 완료 불가**

### 품질 기준
- 테스트 커버리지 80% 이상 유지
- TypeScript 컴파일 에러 0개
- ESLint 규칙 100% 준수
- WCAG 2.1 AA 수준 접근성 준수

### 보안 원칙
- 쿠키에 secure, sameSite 옵션 필수 설정
- 민감한 정보는 localStorage 저장 금지
- 모든 사용자 입력에 XSS 방지 처리 적용
- 환경변수에 민감한 정보 직접 저장 금지

## 📚 학습 순서 권장

### 신규 AI 코더
1. **개발 워크플로우 지침** (필수, 최우선)
2. **코딩 표준 지침** (코드 작성 전 숙지)
3. **테스트 작성 지침** (TDD 구현을 위한 필수)
4. **보안 지침** (보안 취약점 방지)
5. **컴포넌트 설정 지침** (프로젝트별 설정)

### 경험이 있는 AI 코더
1. **개발 워크플로우 지침** - 프로젝트별 특수 규칙 확인
2. **보안 지침** - 보안 요구사항 점검  
3. **컴포넌트 설정 지침** - 프로젝트별 컴포넌트 사용법

## 🔄 문서 업데이트

### 언제 문서를 업데이트해야 하는가?
- 새로운 개발 패턴이나 베스트 프랙티스 발견 시
- 보안 취약점이나 새로운 보안 요구사항 등장 시  
- 프로젝트 구조나 도구가 변경될 때
- 테스트 패턴이나 코딩 표준이 변경될 때

### 업데이트 원칙
- 기존 룰과 충돌하지 않도록 주의
- 변경 사항은 명확한 근거와 함께 문서화
- 예외 사항은 명시적으로 표기
- 실제 코드 예시와 함께 설명

## ❓ 자주 묻는 질문

### Q: 워크플로우를 일부 건너뛰어도 되나요?
**A: 절대 안됩니다.** 8단계 워크플로우는 품질 보장을 위한 최소 요구사항입니다. 예외는 긴급 버그 수정 시에만 허용되며, 이 경우에도 최소한 단위 테스트는 반드시 작성해야 합니다.

### Q: 테스트 커버리지가 80% 미만이어도 되나요?
**A: 안됩니다.** 80%는 최소 기준이며, 가능한 90% 이상을 목표로 해야 합니다. 커버리지가 부족한 경우 추가 테스트 케이스를 작성해야 합니다.

### Q: 보안 지침을 모두 적용하기 어려운데요?
**A: 보안은 협상 불가능한 요구사항입니다.** 특히 쿠키 보안 설정, XSS 방지, 환경변수 관리는 반드시 적용해야 합니다. 적용이 어려운 경우 기술적 대안을 찾아야 합니다.

### Q: 스토리북 작성을 생략해도 되나요?
**A: 안됩니다.** 스토리북은 컴포넌트 문서화와 시각적 테스트를 위한 필수 도구입니다. 모든 UI 컴포넌트는 반드시 스토리북을 작성해야 합니다.
