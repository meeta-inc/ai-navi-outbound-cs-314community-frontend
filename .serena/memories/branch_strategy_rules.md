# 브랜치 전략 및 PR 규칙

## 🚨 중요: PR 생성 전 필수 확인 사항

### 1. 타겟 브랜치 확인
**절대 규칙**: PR을 생성하기 전에 반드시 사용자에게 타겟 브랜치를 명시적으로 확인해야 함

```
❌ 잘못된 예: "develop 브랜치에 PR 만들겠습니다" (가정)
✅ 올바른 예: "PR을 만들기 전에 확인합니다. 타겟 브랜치는 dev2가 맞나요?"
```

### 2. 이 프로젝트의 브랜치 구조
- **dev2**: 주요 개발 브랜치 (PRIMARY)
- **develop**: 보조 개발 브랜치
- **main/master**: 프로덕션 브랜치

### 3. PR 생성 워크플로우
1. 사용자가 "PR 만들어주세요"라고 요청 시:
   - 먼저 `git branch -r` 로 원격 브랜치 목록 확인
   - 사용자에게 타겟 브랜치 확인 질문
   - 명시적 확인 후 PR 생성

2. 사용자가 타겟 브랜치를 명시한 경우:
   - "dev2에 PR 만들어주세요" → dev2로 직접 생성
   - 그렇지 않으면 반드시 확인

### 4. 기본 가정 금지
- HEAD 브랜치나 default 브랜치를 자동으로 타겟으로 설정하지 말 것
- develop이 HEAD라고 해서 자동으로 선택하지 말 것

### 5. PR 제목 규칙
- 한글 PR: dev2가 타겟인 경우
- 영문 PR: develop/main이 타겟인 경우 (프로젝트 컨벤션에 따라)

## 체크리스트
PR 생성 전 확인:
- [ ] 타겟 브랜치를 사용자에게 확인했는가?
- [ ] dev2가 주요 개발 브랜치임을 인지하고 있는가?
- [ ] 브랜치 이름을 명시적으로 언급했는가?
